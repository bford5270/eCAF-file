# Hard-rule self-review

CLAUDE.md requires a self-review against the "Hard rules" section at the end of
every build phase. This is that review for the completed build.

`tools/lint_hard_rules.py` automates ten of these checks and passes. The table
below records where each rule is satisfied, and — more usefully — **how it would
have to be broken**, so a reviewer knows what to look for in a future change.

| Rule | Where it is satisfied | How it breaks |
|---|---|---|
| No CUI/PHI in build artifacts | Sample data is `PROVIDER, SAMPLE A.` / FIN `TEST0000001` / `@test.invalid` addresses, generated by `tools/build_lists.py`. Linter: `rule_sample_data_is_fake` | Someone hand-edits a CSV in `dist/lists/` instead of editing the generator |
| FIN is the only encounter identifier | No MRN/SSN/DOB/patient-name column in `schemas/lists.json`; S3 has one encounter-identity control; `migrate_ewp.py` drops forbidden keys and reports them. Linter: `rule_no_patient_identifiers` | A "just the last four" request gets treated as a UI change rather than a schema change |
| CUI + § 1102 marking on every screen and template | `cmpCUIFooter` on all nine screens; header **and** footer in all four .docx; `DocHtmlHead`/`DocHtmlFoot` in the HTML generator. Linter: `rule_cui_marking` | A new screen ships without the component — the linter catches this |
| No auto-rating of DHA 455 item 12 | The 455 template's item 12 is a bordered table with **zero content controls**; S6 renders an unbound rectangle; `DocItem12Block()` emits empty cells. Linter: `rule_no_item12_rating` | Someone adds a content control to "make F6 tidier". There is currently nothing to bind, which is the protection |
| Denominator integrity | One predicate, `CountsInDenominator`, reading `eCAF_Config!DenominatorReviewTypes`. Every aggregate routes through it. F5 reads the same config. Linter: `rule_denominator_is_data` | A new gallery filters `ReviewType = "Peer"` directly — the linter catches the literal |
| Normalize "not met" at write time | The MET/NOT_MET/NA radio `Items` **are** the stored strings, so no mapping step exists; `migrate_ewp.py` refuses to guess an unknown variant and exits non-zero. Linter: `rule_canonical_results` | A dropdown with friendly display labels ("Not met") mapped to storage values |
| Standards drive the instrument | S4's gallery filters `eCAF_Standards`; no standard ID appears in any formula; S8 adds standards with no republish. Tested in dry-run §4 | A `Switch()` over standard IDs, or a column-per-standard table |
| Specialty standards ship as drafts | All 12 specialty standards in the seed are `DRAFT-VALIDATE`; S8 forces new and edited standards back to DRAFT-VALIDATE; DHA-sourced standards keep verbatim citations. Linter: `rule_specialty_standards_are_draft` | S8's save path lets an author set ACTIVE directly |
| Business-day math excludes weekends + federal holidays | `AddBusinessDays` / `BusinessDaysBetween` UDFs filter against `colHolidays`; `schemas/holidays.csv` generated from 5 U.S.C. § 6103; F1/F2 use the same list | Someone replaces the UDF with weekday arithmetic, which is correct until a holiday falls in the span |
| Delegation on indexed columns | Every gallery filters server-side on `"indexed": true` columns, then applies non-delegable predicates in memory. Linter: `rule_indexes_declared` | Moving `ReviewType` into the delegated `Filter` — tidier, and silently caps every denominator |

## Rules this build cannot satisfy on its own

Three things are only true if the operator does them in the browser. They are
listed in `dist/lists/provisioning-runbook.md` and gated in `docs/dry-run.md`:

1. **Broken inheritance and the five permission groups.** This is the actual
   § 1102 boundary. Every role check in the app is UX — a user who reaches a
   screen they should not see still gets access denied by SharePoint on every
   read, and that is the only reason the app is safe. Dry-run §1 tests it by
   direct item URL, not through the app.
2. **F1's item-level permission stamping**, tested with two accounts before any
   real data.
3. **Phase 0 approval** from the tenant/RMF POC for a citizen-developed app
   holding § 1102 / CUI content.

## Open item — carried, not closed

**`dist/app/src/fixed-instrument.json` is derived, not transcribed.**

CLAUDE.md and `app/app-spec.md` mandate "the DHA 455 item 11 element block" and
"16 competency constructs across the six domains", but neither enumerates them,
and neither DHA Form 455 nor the DHA FPPE Template was supplied to this build.

The four item 11 elements come from the `455-I11:<key>` tokens that actually
appear in `standards-seed.csv` (standardofcare, medication, blood, consults). The
16 constructs come from the FPPE Section 4 subsections cited in that same seed,
expanded across the six named domains.

This is flagged in the file itself, gated in `docs/dry-run.md` Gate 0, and
enforced structurally: `tools/lint_hard_rules.py` validates every
`455-I11:<key>` token in the standards library against that file, so correcting
the element set will fail the lint until the standards that reference it are
corrected too.

**Nothing downstream is hard-coded to it.** Editing that one file and re-running
`tools/build_lists.py` and `tools/build_templates.py` propagates the correction
through the sample data, the review screen, the aggregation, and the .docx
templates. But it must be done by someone holding the actual forms, before any
real review is entered.
